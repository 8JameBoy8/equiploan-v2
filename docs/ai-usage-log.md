# บันทึกการใช้ AI (Claude Code)

## เฟส 1 — โครงโปรเจกต์ ฐานข้อมูล ระบบล็อกอิน/บทบาท (2026-11-16)

### สิ่งที่ AI สร้าง
- `.gitignore`, `.nvmrc` (Node 24), `README.md` (วิธีติดตั้งและวิธีทดสอบ)
- `db/schema.sql` — ตาราง `users`, `equipment`, `loans` (มี `purpose` VARCHAR(500) ไม่บังคับ)
  และ unique index ที่กันไม่ให้อุปกรณ์ชิ้นเดียวมีคำขอ approved พร้อมกัน 2 รายการ
- `backend/` — Express 5:
  - `/healthz`, `/readyz`
  - `POST /api/auth/register`, `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/me`
  - middleware `requireAuth` และ `requireRole` (`src/middleware/auth.js`)
  - `GET /api/admin/ping` (endpoint ชั่วคราวไว้ทดสอบสิทธิ์ admin)
  - สร้างบัญชี admin จาก `.env` ตอนเริ่มทำงาน (`src/seedAdmin.js`)
  - `npm run db:init` สร้างตารางจาก `db/schema.sql`
- `frontend/` — Next.js 16 + Tailwind 4: หน้า `/login`, `/register`, `/` (member, เมนูบน),
  `/admin` (admin, เมนูข้าง), rewrites `/api/*` → backend, ชื่อชมรมอยู่ที่ `lib/config.js`

### การตัดสินใจที่ควรรู้
- session ใช้ JWT ใน httpOnly cookie (อายุ 7 วัน) เพื่อไม่ต้องเพิ่มตารางนอกเหนือจาก 3 ตาราง
  ข้อจำกัด: ล็อกเอาท์คือการลบ cookie ฝั่งเบราว์เซอร์ token ที่ถูกคัดลอกไปจะยังใช้ได้จนหมดอายุ
- บทบาทเก็บอยู่ใน token ด้วย ถ้าเปลี่ยนบทบาทใน DB ผู้ใช้ต้องล็อกอินใหม่ BE จึงจะเห็นบทบาทใหม่
- ใช้ `bcryptjs` (JavaScript ล้วน) แทน `bcrypt` เพื่อไม่ต้องติดตั้ง build tools บน Windows
- FE ตรวจบทบาทเพื่อแสดงเมนูและหน้า "ไม่มีสิทธิ์" เท่านั้น การกันสิทธิ์จริงทำที่ BE

### ผลการทดสอบที่ AI รันแล้ว (PostgreSQL 17 ติดตั้งตรงบน Windows)
- curl: healthz 200, readyz 200, สมัคร 201, สมัครอีเมลซ้ำ 409, รหัสสั้น 400, ไม่มี body 400,
  me 200, **member เรียก /api/admin/ping ได้ 403**, ล็อกเอาท์แล้ว me ได้ 401,
  รหัสผิด 401, admin ping 200, cookie ปลอม 401
- เบราว์เซอร์: สมัครแล้วเข้าหน้าหลักสมาชิก (เมนูบน), `document.cookie` ว่าง (cookie เป็น httpOnly),
  member เปิด `/admin` เห็นหน้า "ไม่มีสิทธิ์เข้าถึง", เปิด `/api/admin/ping` ผ่าน rewrite ได้ 403,
  ล็อกเอาท์แล้วเปิด `/` ถูกพาไป `/login`, admin ล็อกอินเห็นเมนูข้าง, admin เปิด `/` ถูกพาไป `/admin`
- หมายเหตุ: curl ใน Git Bash ส่งภาษาไทยเป็น codepage ของ Windows ทำให้ชื่อเพี้ยน (ไม่ใช่บั๊กของแอป)
  ทดสอบภาษาไทยผ่านเบราว์เซอร์แทน
- เพิ่ม `.claude/launch.json` ไว้เปิด frontend ในหน้าต่างพรีวิวของ Claude Code

## เฟส 2 — จัดการอุปกรณ์และรูป (2026-11-16)

### สิ่งที่ AI สร้าง/แก้
- `db/schema.sql` — เพิ่มคอลัมน์ `equipment.category` (VARCHAR(50), ใช้ `ALTER ... IF NOT EXISTS` ให้ DB เดิมอัปเดตได้)
- `backend/src/upload.js` — รับรูปด้วย multer 2.5.0 (เก็บในหน่วยความจำก่อน), ตรวจ 2 ชั้น
  (นามสกุล+mimetype แล้วตรวจ magic bytes), จำกัด 5MB (ตอบ 413), ตั้งชื่อไฟล์ใหม่ด้วย UUID,
  ลบรูปเก่าเมื่อเปลี่ยนรูป
- `backend/src/routes/equipment.js` — `GET /api/equipment`, `GET /api/equipment/:id`,
  `GET /api/equipment/:id/image` (ต้องล็อกอิน), `POST` และ `PUT` (admin เท่านั้น)
  สถานะว่าง/ถูกยืมคำนวณจาก `loans` ที่ `approved` ไม่ได้เก็บเป็นคอลัมน์
- `backend/scripts/db-seed.js` + `npm run db:seed` — อุปกรณ์สมมติ 10 ชิ้น 4 หมวด (ไม่มี loans สมมติ ตามที่ผู้ใช้สั่ง)
- `frontend/` — หน้า `/equipment` (member), `/admin/equipment`, `/admin/equipment/new`,
  `/admin/equipment/[id]/edit`; คอมโพเนนต์ `EquipmentCard`, `EquipmentGrid`, `EquipmentForm`, `PageHeader`;
  `lib/api.js` รองรับส่ง FormData; เมนู "อุปกรณ์"/"จัดการอุปกรณ์" ใช้งานได้แล้ว

### การตัดสินใจที่ควรรู้
- ไม่เปิดโฟลเดอร์รูปเป็น static: รูปทุกรูปต้องผ่าน endpoint ที่ตรวจการล็อกอิน (เฟส 3 จะใช้วิธีเดียวกันกับรูปตอนคืน
  เพื่อให้เห็นได้เฉพาะ admin และเจ้าของคำขอ)
- URL รูปมี `?v=เวลาแก้ไขล่าสุด` เพื่อให้เบราว์เซอร์โหลดรูปใหม่หลังเปลี่ยนรูป
- ไม่มีการลบอุปกรณ์ เพราะฟีเจอร์ระบุแค่ "เพิ่ม/แก้"
- หมวดเป็นข้อความอิสระ (มีรายการหมวดเดิมให้เลือก) ไม่ใช่รายการตายตัว
- ข้อจำกัด: ถ้าบันทึกไฟล์แล้วแต่ INSERT ลง DB ล้มเหลว จะมีไฟล์ค้างในโฟลเดอร์ (โอกาสต่ำ ยังไม่จัดการ)

### ผลการทดสอบที่ AI รันแล้ว
- curl: ไม่ล็อกอินดูรายการ 401, member เพิ่ม/แก้ 403, admin เพิ่ม png 201,
  gif 400, gif ที่เปลี่ยนชื่อเป็น .png 400 (จับได้จาก magic bytes), ไฟล์ข้อความชื่อ .jpg 400,
  ไฟล์ 6MB 413 (ทั้งเรียก BE ตรงและผ่าน rewrite ของ Next.js), ไม่กรอกชื่อ 400,
  ดูรูปไม่ล็อกอิน 401, ดูรูป member 200 และไบต์ตรงกับไฟล์ต้นฉบับ, แก้รูปแล้วไฟล์เก่าถูกลบ,
  แก้ด้วยไฟล์ปลอมได้ 400 และรูปเดิมยังอยู่, id ไม่มีอยู่/ไม่ใช่ตัวเลข 404
- เบราว์เซอร์: admin เพิ่มอุปกรณ์พร้อมรูปและแก้ไข/เปลี่ยนรูปได้, ฟอร์มเตือนไฟล์ gif และไฟล์ 6MB ก่อนส่ง,
  member เห็นการ์ด 10+ ใบไม่มีปุ่มแก้ไข และเข้า `/admin/equipment/new` ไม่ได้,
  ป้าย "ถูกยืม" แสดงถูก (ทดสอบด้วย loan ชั่วคราวแล้วลบทิ้ง), จอมือถือ 375px ไม่มีเลื่อนแนวนอน
- ข้อมูลทดสอบทั้งหมด (อุปกรณ์ทดสอบ, loan ชั่วคราว, ไฟล์รูป) ลบออกแล้ว เหลืออุปกรณ์สมมติ 10 ชิ้น

## เฟส 3 — workflow การยืมและคืน (2026-11-16)

### สิ่งที่ AI สร้าง/แก้
- ไม่ต้องแก้ schema: `loans.purpose` VARCHAR(500) มีอยู่แล้วตั้งแต่เฟส 1 (ตรวจกับ DB จริงแล้ว)
- `backend/src/routes/loans.js` — `POST /api/loans` (member), `GET /api/loans` (member เห็นของตัวเอง,
  admin เห็นทั้งหมด), `POST /:id/approve`, `POST /:id/reject` (admin), `POST /:id/return` (เจ้าของ, รูปบังคับ),
  `GET /:id/return-image` (admin หรือเจ้าของเท่านั้น)
- `frontend/` — หน้า `/borrow`, `/my-loans`, `/my-loans/[id]/return`, `/admin/loans`;
  ปุ่ม "ขอยืม" บนการ์ดอุปกรณ์; คอมโพเนนต์ `LoanStatusBadge`, `ImageModal`;
  `lib/imageFile.js` (ตรวจไฟล์รูป ใช้ร่วมกับฟอร์มอุปกรณ์), `lib/format.js` (วันเวลาไทย); เมนู member เพิ่ม "ขอยืม"

### การตัดสินใจที่ควรรู้
- นับความยาววัตถุประสงค์เป็นตัวอักษรจริง (`[...text].length`) ทั้ง FE และ BE ให้ตรงกับ VARCHAR(500)
- หลายคนขอยืมอุปกรณ์ชิ้นเดียวกันได้ระหว่างรออนุมัติ แต่คนเดิมขอชิ้นเดิมซ้ำไม่ได้;
  อนุมัติได้คนเดียว (ตรวจในโค้ด + unique index ใน DB กันอีกชั้น); คำขออื่นที่ค้างอยู่ admin ปฏิเสธเอง
- admin ส่งคำขอยืมไม่ได้ (403) และคืนแทน member ไม่ได้
- UPDATE ใช้เงื่อนไข `WHERE status = ...` กันกรณีกดพร้อมกันสองครั้ง
- รูปตอนคืนเก็บในโฟลเดอร์เดียวกับรูปอุปกรณ์ แต่เรียกผ่าน endpoint ที่ตรวจสิทธิ์ของคำขอนั้น

### ผลการทดสอบที่ AI รันแล้ว
- curl (member 2 คน + admin): สร้างคำขอ 201, admin สร้าง 403, purpose 501 ตัว 400 / 500 ตัวผ่าน,
  อุปกรณ์ไม่มี 404, ขอซ้ำขณะรออนุมัติ 409, member อนุมัติ 403, อนุมัติซ้ำ 409,
  อนุมัติคำขอที่ 2 ของอุปกรณ์เดียวกัน 409, ขออุปกรณ์ที่ถูกยืม 409, คืนคำขอ requested/rejected 409,
  คืนไม่มีรูป 400, คืนของคนอื่น 403, admin คืน 403, รูปคืนปลอม/gif 400, รูป 6MB 413, คืนสำเร็จ 200,
  คืนซ้ำ 409, รูปคืน: เจ้าของ/admin 200, member อื่น 403, ไม่ล็อกอิน 401;
  หลังคืนแล้วอุปกรณ์กลับเป็น "ว่าง" และขอยืมใหม่ได้; ตรวจใน DB ว่า decided_by/decided_at/returned_at ถูกบันทึก
- เบราว์เซอร์: กด "ขอยืม" จากการ์ด → เลือกไว้ให้พร้อมรูปและชื่อ, เปลี่ยน dropdown แล้วรูป/ชื่อเปลี่ยนทันที,
  ตัวนับ 501/500 ปิดปุ่มส่ง, ขอซ้ำขึ้นข้อความ 409, admin เห็นวัตถุประสงค์และอนุมัติได้,
  การ์ดเปลี่ยนเป็น "ถูกยืมอยู่", ลิงก์ขอยืมของชิ้นที่ถูกยืมขึ้นคำเตือน, ฟอร์มคืนปิดปุ่มจนกว่าจะเลือกรูป
  และปฏิเสธ pdf, คืนสำเร็จ, admin เปิดรูปคืนใน modal ได้, จอมือถือ 375px ไม่มีเลื่อนแนวนอน
- ลบข้อมูลทดสอบแล้ว: loans ทั้งหมด, บัญชี member2@test.local, รูปทดสอบ (เหลืออุปกรณ์สมมติ 10 ชิ้นไม่มีรูป,
  บัญชี admin และ member1@test.local)

## เพิ่มฟีเจอร์: admin ลบอุปกรณ์ (2026-11-18)

ผู้ใช้ขอเพิ่มหลังทดสอบระบบ และยืนยันแผนแบบ soft delete แล้ว (เพิ่มลงหัวข้อฟีเจอร์ใน CLAUDE.md ด้วย)

### สิ่งที่ AI สร้าง/แก้
- `db/schema.sql` — เพิ่มคอลัมน์ `equipment.deleted_at` (ALTER ... IF NOT EXISTS รันซ้ำได้)
- `backend/src/routes/equipment.js` — `DELETE /api/equipment/:id` (admin เท่านั้น) ใส่ `deleted_at = now()`
  ตอบ 409 ถ้ามีคำขอ requested/approved (ตรวจใน UPDATE เดียวกันด้วย NOT EXISTS), ตอบ 404 ถ้าไม่พบหรือลบไปแล้ว;
  GET รายการ/รายชิ้น และ PUT ไม่รวมอุปกรณ์ที่ลบแล้ว; endpoint รูปยังส่งรูปได้เพื่อให้ประวัติแสดงรูป; ไม่ลบไฟล์รูป
- `backend/src/routes/loans.js` — ขอยืมอุปกรณ์ที่ลบแล้วไม่ได้ (404)
- `frontend/components/ConfirmDialog.js` (ใหม่) หน้าต่างยืนยัน แสดงเหตุผลเมื่อลบไม่ได้, `Icons.js` เพิ่ม TrashIcon,
  `EquipmentGrid.js` ส่ง `reload` ให้ปุ่มบนการ์ด, `app/admin/equipment/page.js` ปุ่ม "แก้ไข" + "ลบ"
- README: หัวข้อวิธีทดสอบฟีเจอร์ลบอุปกรณ์

### ผลการทดสอบที่ AI รันแล้ว
- API: member ลบ → 403, ไม่ล็อกอิน → 401, มีคำขอรออนุมัติ → 409, ถูกยืมอยู่ → 409, คืนแล้ว/ถูกปฏิเสธ/ไม่เคยยืม → ลบได้,
  ลบซ้ำ → 404, อุปกรณ์ที่ลบไม่อยู่ในรายการ, GET/PUT/ขอยืม → 404, ประวัติคำขอยังมีชื่ออุปกรณ์และเปิดรูปคืนได้
- เบราว์เซอร์: ลบสำเร็จแล้วการ์ดหาย + ข้อความแจ้ง, ลบไม่ได้แสดงเหตุผลในหน้าต่าง, Esc/ยกเลิกปิดได้,
  จอ 375px ไม่เลื่อนแนวนอน; `next build` ผ่าน
- ลบข้อมูลที่ผู้ใช้ทดสอบ (อุปกรณ์ "เทส1", คำขอที่คืนแล้ว 2 รายการ, รูป 3 ไฟล์) และข้อมูลที่ AI สร้างตอนทดสอบแล้ว
  เหลืออุปกรณ์สมมติ 10 ชิ้น, admin, member1@test.local, ตาราง loans ว่าง, โฟลเดอร์ uploads ว่าง
